# ADR-0003：TotalCharges 空值與估算規則

- 狀態：已採用（2026-11-20）

## 非工程背景讀者閱讀版

- 「累計費用」是顧客到目前為止付的總金額。原始資料有 11 筆是空白，查證後全部是剛加入、還沒繳過費的新客戶，所以補成 0 是合理的。
- 使用者在網頁上可以不填累計費用，系統用「在網月數 × 月費」估算，畫面會註明這是估算值。
- 估算和實際值的落差通常很小：一半的顧客誤差在 2% 以內，九成在 7.6% 以內。
- 限制：估算值超過 10,000 時系統會要求手動填寫，因為這已超出訓練資料的範圍（最大約 8,700）。

以下是完整技術內容，供工程團隊實作參考。

## 背景

- 原始 CSV 的 `TotalCharges` 有 11 列為空白字串 `" "`；這 11 列 `tenure` 全為 0，且全資料集 `tenure = 0` 的也恰好是這 11 列（AC-4.3）。
- 使用者不容易知道累計金額，需求 Q3 決定此欄選填。

## 選項

| 選項 | 說明 |
|---|---|
| A. 刪除空白列 | 丟掉新客戶資料，推論時仍需處理缺值 |
| B. 以中位數填補 | 對 tenure = 0 的新客戶明顯錯誤 |
| C. 以 tenure × MonthlyCharges 估算 | 符合業務意義，訓練與推論可用同一規則 |

## 決定

採 C，規則只在 `churn_core.imputation` 實作一次，訓練與推論共用：

- 估算值 = `Decimal(str(tenure)) × Decimal(str(MonthlyCharges))`，以 half-up 取 2 位小數。乘法用 Decimal 精確計算，避免 3 × 0.075 被浮點誤差捨成 0.22。
- 手填值同樣 half-up 取 2 位；API 回應的 `total_charges.value` 即實際用於預測的值。
- 推論時估算值 > 10,000 → 422（`field = TotalCharges`、`type = out_of_range`）；訓練資料不做上限檢查。
- 11 筆空白列的估算結果為 0，與「尚未繳費」一致。

估算誤差（訓練子集中有填且 > 0 的 4,500 列，|實際 − 估算| / 實際）：中位數 0.0198、P90 0.0756。

## 後果

- 訓練與推論對缺值的處理完全一致（`test_feature_parity` 逐位元驗證）。
- 估算值會成為影響因素之一，標籤顯示為「累計費用：$100.00（估算）」。
- 估算誤差已揭露於 README 已知限制。
