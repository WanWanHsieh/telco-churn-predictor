# ADR-0004：不使用資料庫

- 狀態：已採用（2026-11-20）

## 非工程背景讀者閱讀版

- 這個系統不保存任何使用者輸入的資料，也不保存預測紀錄，所以不需要資料庫。
- 好處是部署簡單、沒有保存個資的風險，啟動只要一行指令。
- 限制：看不到過去的預測歷史；需要時再加入，已列為未來功能。

以下是完整技術內容，供工程團隊實作參考。

## 背景

- MVP 的資料都是唯讀：模型檔、前處理參數、成效指標皆為訓練產物，隨映像發布。
- 單筆與批次預測都是無狀態計算；需求明列「不做預測歷史」（requirements 4.3）。

## 選項

| 選項 | 優點 | 缺點 |
|---|---|---|
| A. PostgreSQL 存預測紀錄 | 可查歷史、可做分析 | 多一個服務、migration、備份與個資治理 |
| B. 不用資料庫，產物以檔案隨映像發布 | 部署最簡單、無資料保存風險 | 無歷史紀錄 |

## 決定

採 B。`models/` 進版控並複製進 backend 映像；批次上傳只在記憶體中處理，不寫檔、不記內容（超過 1 MB 時框架會短暫寫入暫存檔，處理完即刪除）。

## 後果

- `docker compose up` 只有 backend 與 frontend 兩個服務，不需設定資料庫連線或機密。
- 服務為唯讀，可水平擴充（目前單 worker，見 design.md 10.2）。
- 未來若加入預測歷史，需新增 PostgreSQL、migration 與個資保存政策（requirements 4.2）。
