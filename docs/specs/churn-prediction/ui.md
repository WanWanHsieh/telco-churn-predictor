# 畫面與流程設計：顧客流失預測 Web App

- 功能代號：churn-prediction
- 依據：requirements.md（F1–F6、AC、NFR）與主管派工單「已決定的事」（Q1 批次納入且最後順位；Q2 切點 30%/60%；Q3 TotalCharges 選填；Q5 繁中；Q6 兩模型；Element Plus；不登入）
- HTML 原型：`docs/specs/churn-prediction/prototype/index.html`（單檔、無外部資源；用純 CSS 模擬 Element Plus 外觀，只為看版面與互動，不是正式程式；成效頁與批次頁數字皆為示意值）
- 專案根目錄沒有 CLAUDE.md、也沒有 `design/`，無既有風格可沿用；本文件的視覺規範以 Element Plus 預設為基底，僅調整會影響對比的顏色（見 8.1）。

## 1. 情境

| 項目 | 內容 |
|---|---|
| 使用者 | 面試官（主要，會實際操作，約 5 分鐘）；留客分析人員（情境角色） |
| 裝置 | 桌機 1280px 為主；手機 375px 必須可用（NFR-9） |
| 最重要的任務 | 填一位顧客的資料，一眼看到「機率、風險等級、為什麼」 |
| 設計方向 | 內部分析工具：白底、灰階為主、單一主色（藍）、風險色只用在結果；不放插圖與裝飾動畫 |

降低面試官操作門檻的決定（新增，理由：19 欄手填耗時，面試官 5 分鐘內要看到結果）：
- 表單頂端放「載入範例」兩顆按鈕：「高風險範例」「低風險範例」，內容即 AC-1.3 與 AC-1.4 的輸入。按下後填入表單，**不會自動預測**，使用者仍需按「預測」。

## 2. 整體導覽與頁面清單

單頁應用，頂部水平導覽列（el-menu mode="horizontal"），無登入、無側邊欄。

| 頁面 | 路由（建議，最終由前端/architect 定） | 導覽文字 | 對應功能 | 優先度 |
|---|---|---|---|---|
| 單筆預測 | `/`（預設首頁） | 單筆預測 | F1、F2 | 必做 |
| 模型成效 | `/performance` | 模型成效 | F3 | 必做 |
| 批次預測 | `/batch` | 批次預測 | F6 | 必做中最後順位（被砍時，導覽項目一併移除，其他頁不受影響） |

導覽列：左側產品名「顧客流失預測」＋副標「Telco Churn Predictor」；右側三個導覽項＋「API 文件」外部連結（開 `/docs`，新分頁，對應 AC-5.2）。
- 目前頁面的導覽項有底線加粗體（不只靠顏色），並設 `aria-current="page"`。
- 手機（<768px）：導覽列改為產品名＋漢堡按鈕，展開為垂直選單（el-drawer 或 el-menu 折疊）；每項高度 >= 44px。
- 全站頁尾固定一行小字：「模型以公開範例資料訓練，僅供展示，不可用於真實決策」（結果區另有一次，見 AC-1.13）。

使用流程（主流程）：進首頁 → （可選）按「載入範例」→ 填表 → 按「預測」→ 右側（手機為下方）出現結果與前 5 因素 → 可修改任一欄位重新預測。出錯時留在同頁、保留已填內容。

## 3. 頁面一：單筆預測（F1、F2）

對應 AC：AC-1.1～1.13、AC-2.1～2.6、NFR-10。

### 3.1 版面

桌機（>=1024px）：兩欄，左欄表單（約 58%）、右欄結果（約 42%，sticky 於視窗頂部下 16px，使用者捲動長表單時結果仍可見）。
手機（<768px）：單欄，表單在上、結果在下；按「預測」成功後自動捲動到結果區並把焦點移到結果標題（`tabindex=-1`，供螢幕報讀器朗讀）。平板（768–1023px）：單欄，欄位兩欄排列。

```
[導覽列]
[頁面標題：單筆顧客流失預測］[載入範例：高風險範例｜低風險範例]
┌──────────── 表單 el-form ───────────┬──────── 結果區 ────────┐
│ 區塊 A 基本資料（4 欄）              │ 空狀態／載入中／結果／錯誤 │
│ 區塊 B 電話與網路服務（9 欄）        │                          │
│ 區塊 C 合約與付款（4 欄）            │                          │
│ 區塊 D 費用（3 欄）                  │                          │
│ [清除]  [預測]（主按鈕）             │                          │
└─────────────────────────────────────┴──────────────────────────┘
```

表單以 el-card 分 4 個區塊（標題見上），每區塊內：桌機 2 欄（el-row/el-col :span=12），手機 1 欄。標籤置於欄位上方（label-position="top"），減少視線左右跳動，手機也一致。必填欄位標籤前不放紅色星號以外的符號；星號之外，欄位標籤旁不另加「(必填)」，但表單頂端一行說明「標示 * 的欄位必填」。

按鈕列：「預測」為 el-button type="primary" size="large"，手機寬度 100%；「清除」為次要（plain）。按鈕列在手機固定於表單底部（sticky bottom），避免需捲到底才找到主按鈕。

### 3.2 表單欄位清單（19 個特徵，AC-1.1）

通則：
- 標籤格式「中文名稱 英文欄位名」，英文名用較小的灰字（對比 >= 4.5:1），方便對照資料集。
- 選項顯示「中文（原始值）」，送出給 API 的值一律是資料集原始值（英文，大小寫與資料集完全一致，AC-1.1）。
- 二元欄位用 el-radio-group（按鈕樣式，el-radio-button），選項少、一眼看完；3 個以上選項用 el-select。
- 預設值：所有欄位預設「未選」（空），讓 AC-1.7 的必填檢查有意義；唯一例外是被連動鎖定的欄位。理由：預設值會讓使用者不經思考就預測，結果失去意義。
- 錯誤訊息：顯示在欄位下方（el-form-item 的 error），紅字加「!」圖示；送出失敗時焦點移到第一個錯誤欄位。必填空白的訊息統一：「請選擇○○」（選擇型）或「請輸入○○」（輸入型）。
- 驗證時機：按「預測」時全部驗證；之後欄位失焦或變更時即時重驗該欄。

- 鎖定欄位的視覺：el-radio-group disabled，已選項顯示「無電話服務」／「無網路服務」，並在欄位旁以灰底標籤「自動設定」標示，不只是變灰。

### 3.4 預測結果呈現（F1、F2，AC-1.2、1.13、2.1～2.5）

結果卡片由上而下：

1. **標題列**：「預測結果」；右側小字「模型：Keras 神經網路」（預測使用的模型，取自 API，見第 9 節）。
2. **機率與等級（主視覺）**
   - 大字：「流失機率 72.4%」（小數 1 位，AC-1.2；字級 40px 粗體，手機 32px）。
   - 風險等級徽章：圖示＋文字，例如「▲ 高風險」「◆ 中風險」「▼ 低風險」，旁邊一行說明：「機率 >= 60%」「機率 30% 至未滿 60%」「機率 < 30%」（切點見 Q2）。
   - 機率尺：水平條 0–100%，分成三段（低 0–30、中 30–60、高 60–100，用淺色區段），30% 與 60% 處有刻度標籤，目前機率以黑色三角指針標示。尺下方標示文字，不靠顏色辨識。
3. **主要影響因素（前 5 大）**
   - 區塊標題「影響此預測的前 5 大因素」。
   - 每列：序號（1–5）｜因素名稱（中文可讀，如「合約類型：月繳」；不可出現內部欄位名，AC-2.2）｜方向標籤｜影響長條與數值。
   - 方向標籤：「↑ 推高風險」（紅系）、「↓ 拉低風險」（綠系）；圖示加文字，兩者缺一不可。
   - 長條：以中線為 0 的發散長條；推高向右、拉低向左；長度為「相對影響大小」，同列右側顯示數值（例如 `+0.31`、`-0.18`；數值定義由 architect 決定，畫面上標題欄位名稱用「影響程度」）。長條 `role="img"`，並有 aria-label：「合約類型：月繳，推高風險，影響程度 0.31」。
   - 由大到小依影響絕對值排序（AC-2.1）；同一輸入順序固定（AC-2.4）。
   - 手機：長條改為列下方獨立一行（因素名稱＋方向標籤在上，長條在下），避免擠壓。
4. **說明句（AC-2.5）**：因素區底下灰字：「這些因素是模型做出判斷的依據，不代表真正的因果關係。」
5. **TotalCharges 註記**：若使用者未填累計費用，結果區顯示一行資訊（el-alert type="info" closable=false）：「累計費用未填寫，已以在網月數 × 月費估算為 $X,XXX.XX。」（估算值由 API 回傳或前端依同公式顯示，見第 9 節）。
6. **固定免責提示（AC-1.13）**：卡片底部固定一行（不可關閉）：「模型以公開範例資料訓練，僅供展示，不可用於真實決策」。

風險等級視覺（8.1 有色碼）：

| 等級 | 切點 | 文字 | 圖示 | 底色/文字色 |
|---|---|---|---|---|
| 低 | < 30% | 低風險 | ▼（向下三角，或 Element Plus `CaretBottom`） | 綠系 |
| 中 | 30% 至 < 60% | 中風險 | ◆（菱形，或 `Minus`） | 琥珀系 |
| 高 | >= 60% | 高風險 | ▲（向上三角，或 `CaretTop`） | 紅系 |

> 切點若依訓練結果微調（Q2 備註），畫面上的說明文字必須由 API 回傳的切點產生，不寫死（見第 9 節）。

## 4. 頁面二：模型成效（F3）

對應 AC：AC-3.1～3.8、NFR-3（成效 API < 300ms，載入狀態仍要設計）。

### 4.1 版面（由上而下，單欄為主，桌機部分區塊並排）

1. **頁面標題與一句導讀**：「模型成效」＋「模型在訓練時從未看過的測試資料上的表現，並與簡單的基準模型比較。」
2. **資料說明區（AC-3.3）**：el-descriptions（桌機 4 欄、手機 1 欄，border）。項目：訓練集筆數、測試集筆數、測試集流失比例、決策門檻值、模型訓練日期。（建議加：隨機種子、模型版本，見第 9 節，非必要）
3. **指標比較表（AC-3.1）**：el-table，列＝兩個模型（「邏輯迴歸（基準）」「Keras 神經網路」），欄＝ROC-AUC、Precision、Recall、F1、Accuracy。
   - 數值顯示 3 位小數。
   - 每個指標欄中較佳者以粗體標示（不靠顏色），表格下方小字「粗體為該指標較佳者」。兩者相同時皆不粗體。
   - ROC-AUC 與 Recall 欄標題加小標「主要指標」（以標籤 el-tag type="info" 呈現）。
   - Accuracy 欄標題旁放資訊圖示（el-tooltip，亦可鍵盤聚焦），並在表格下方直接顯示說明文字（不隱藏在 tooltip，AC-3.4）：「資料約 26.5% 為流失，若全部猜『不流失』就有約 73.5% 的 Accuracy，所以本專案以 ROC-AUC 與 Recall 為主要指標。」（26.5% 與 73.5% 應由 API 的實際流失比例計算，見第 9 節）
   - 手機：el-table 不橫向捲動，改為「指標 × 模型」的轉置表（列＝5 個指標，欄＝2 個模型），2 欄數值在 375px 內可完整顯示（AC-3.8）。
4. **圖表區**（桌機兩欄並排，手機單欄堆疊）
   - 左：**ROC 曲線**（折線圖）：兩個模型曲線疊圖＋對角虛線（隨機猜測基準）；X 軸「偽陽性率（False Positive Rate）」、Y 軸「真陽性率（True Positive Rate）」；圖例含模型名與 AUC 數值，如「Keras 神經網路（AUC 0.846）」；兩條線除顏色外，一條實線、一條長虛線＋不同標記形狀。
   - 右：**混淆矩陣**（Keras 模型，2×2 熱度格）：4 格各含：數量、格子意義文字（「實際流失、預測流失」「實際未流失、預測流失」等，AC-3.2）、佔比。列/欄標題「實際」「預測」。顏色只表示數量深淺，意義靠文字。
   - 圖表下方各附一組「資料表檢視」摺疊（el-collapse），內含相同數據的純文字表格，供報讀器與無法看圖者使用。
5. **白話說明區（AC-3.5）**：「如何處理類別不平衡」「為什麼選這個決策門檻」，各 1–2 句，合計 3 句內；用 el-card 淺灰底。
6. 頁尾免責提示（全站頁尾）。

## 5. 頁面三：批次預測（F6，最後順位）

對應 AC：AC-6.1～6.12。優先度最低；被砍時整頁與導覽項目移除。

### 5.1 版面

單欄、最大寬度 960px 置中，由上而下依狀態切換內容（同一頁面三階段，不跳頁）：

**階段 A：上傳**
- 說明文字：「上傳顧客名單 CSV，一次取得每位顧客的流失風險。欄位需與單筆預測相同（共 19 欄），可另加 customerID 欄位以便對照。」
- 規格摘要（一行小字）：「檔案格式：CSV，上限 5 MB 或 10,000 列」（AC-6.8，數值由 API 回傳，見第 9 節）。
- 「下載範本 CSV」連結按鈕（el-button link/plain，含下載圖示），AC-6.1。
- 上傳區：el-upload drag，`accept=".csv"`，`:limit="1"`，`:auto-upload="false"`；內文「將 CSV 檔拖曳到此，或按一下選擇檔案」。同時可鍵盤操作（Enter/Space 開啟檔案選擇）。
- 選定檔案後：顯示檔名、大小、「移除」連結；出現主按鈕「開始預測」（未選檔時 disabled）。

**階段 B：處理中**
- 「開始預測」變 loading＋disabled，上傳區 disabled（AC-6.10）；顯示「正在預測 N 筆資料…」（el-progress 不確定進度 `indeterminate`，因為 API 一次回結果）。不提供取消按鈕（避免複雜度）。

**階段 C：結果**
1. 摘要列（AC-6.5）：4 張等寬小卡：「總筆數」「高風險 N 筆」「中風險 N 筆」「低風險 N 筆」；每張以風險徽章（圖示＋文字）加數字，非只靠顏色。手機為 2×2。
2. 工具列：風險篩選（el-radio-group 按鈕樣式：全部／高／中／低，各附筆數）、「下載結果 CSV」按鈕（AC-6.4）、「重新上傳」次要按鈕。
3. 結果表格（el-table，AC-6.2、6.3）：欄位＝序號、customerID（有才顯示）、流失機率（右對齊，百分比 1 位）、風險等級（徽章）。預設依機率由高到低；機率與風險等級欄可點標題排序（sortable，並以箭頭圖示與 `aria-sort` 指示）。分頁：el-pagination，每頁 20 筆（> 20 筆時顯示），手機用 `small` 與 `layout="prev, pager, next"`。
   - 表格只顯示「結果核心欄位」；原始 19 欄在下載的 CSV 中帶回，不全部列在畫面（避免橫向過寬）。手機保持 4 欄以內，不橫向捲動。
   - 批次結果不提供每筆「前 5 因素」（批次 API 不需回因素，控制範圍）。

## 9. 需要 architect 在 API 提供的資料欄位（供 API 設計參考，非規格）

單筆預測回應（AC-2.6：機率與因素同一次回應）：
- 流失機率（0–1 浮點）
- 風險等級（低／中／高的代碼）與所用切點（兩個門檻值，供畫面說明文字）
- 使用的模型名稱與版本
- 前 5 大因素陣列，依影響大小排序；每項需含：中文顯示名稱（如「合約類型：月繳」，由後端產生以避免前端維護對照表）、方向（推高／拉低）、影響數值（帶正負號）
- TotalCharges 是否為系統估算（布林）與估算值
- 422 錯誤需含「欄位名稱＋原因」清單，前端可對應到欄位下方（AC-1.8）；錯誤 JSON 結構一致（NFR-7）；503 回應可由前端判斷為「服務暫時無法使用」（AC-1.9）

欄位合法範圍（供前端驗證與後端一致）：tenure 0–72 整數、MonthlyCharges 0–200；TotalCharges 上限待定（見待確認 1）。

成效頁資料（一支 API 一次回齊，AC-3.1～3.6）：
- 兩個模型（邏輯迴歸、Keras）各自：ROC-AUC、Precision、Recall、F1、Accuracy
- Keras 混淆矩陣 4 個數值（TN、FP、FN、TP）
- 兩個模型的 ROC 曲線點陣列（FPR、TPR），及各自 AUC
- 訓練集筆數、測試集筆數、測試集流失比例、決策門檻值、訓練日期；（建議）亂數種子、模型版本
- 不平衡處理方式與門檻選擇理由的白話文字（AC-3.5；由訓練流程輸出的檔案提供或由前端靜態文案，請 architect 決定來源，但數字須來自成效檔，AC-3.6）
- 資料不存在時回可區分的狀態（供空狀態，非一般錯誤）
- 圖表類型：ROC 曲線（折線，雙線疊圖＋對角基準線）、混淆矩陣（2×2 熱度格）、因素長條圖（發散長條）；圖表庫選擇交 architect；若選用 canvas 型圖表，需能提供資料表替代（見 8.2）

批次預測：
- 範本 CSV 下載（至少 2 列範例，AC-6.1）
- 預測結果：每列 customerID（若有）、流失機率、風險等級；摘要總筆數與各等級筆數（可由前端計算）
- 結果 CSV 下載（含原始欄位＋機率＋風險等級；UTF-8 BOM）
- 上限值（5 MB、10,000 列），供畫面文案取用
- 錯誤：缺少欄位清單、不合法列（列號＋欄位＋原因，API 可回全部，前端截取前 20 筆並顯示「另有 N 筆」；或 API 直接回前 20 筆與總數），檔案超限、非 CSV／空檔需有可區分的錯誤代碼

## 11. 給前端的實作重點
- Element Plus 按需引入；覆寫主題變數集中在一個樣式檔（`--el-color-primary` 與 8.1 的風險色變數）。
- 表單狀態與連動規則用 Pinia store 或 composable 管理，並獨立成純函式便於單元測試（AC-5.7）。
- 風險等級徽章、方向標籤、因素長條做成共用元件（單筆頁與成效頁、批次頁都會用到風險徽章）。
- 圖表需在父容器寬度變化時自動重繪（手機旋轉）。
- 原型 `prototype/index.html` 僅供視覺與互動參照，其內的假資料與假預測邏輯不可帶入正式程式。

## 12. 待使用者／architect 決定

1. TotalCharges 上限：資料集最大約 8,700，建議驗證 0–10,000，請 architect 與後端對齊（目前為假設）。
2. 「載入範例」按鈕為新增功能（非 PM 需求）：建議保留，若不要請告知；不影響任何 AC。
3. 因素影響數值的定義（SHAP 值、機率變化量等）由 architect 決定；畫面僅預留「影響程度」欄與正負號。
4. 手機「預測」按鈕 sticky 底部為建議，若與 Element Plus 版面衝突可降為一般位置。
5. 替代方案（僅一個）：預測頁改為「分步驟精靈」（4 步，每步一區塊），手機較易填，但桌機操作步驟變多且不利面試官快速試玩，故不推薦。
